## Ergo, what is a Task?

A task is a single unit of work within a job that executes such as a notebook, script, query etc.

- Tasks do the actual work
- These can be pretty broad in terms of what is an acceptable "type" of task

> Jobs consist of one or more tasks, and there are many different task types available. You can use Databricks Notebooks in any supported language, Python Scripts, Python Wheels for packaged code, SQL Files and Queries for data transformations, DLT (Declarative Pipelines), dbt for data transformation, Java JAR files, Spark Submit jobs for legacy Spark applications, AI/BI Dashboards for visualization, and even Power BI integration.

Scheluding Options for JObs

Outside of manual triggers (i.e. you handselect and run a job), there are three other options to run trigger a job run

- Scheduled -
  - Simple (periodiic job runs daily, hourly or weekly basis)
  - Advanced: Allows you schedule jobs using CRON syntax for precise timing
- Table Update - If a table in Azure Databricks updates, this trigger can be set to run
- Continuous - runs repeatedly with a short interval in between runs. These keep a job running indefinitely by launching a new run immediately after the previous one finishes or fails.
- FIle arrival - checks an external location/volume for new files
  - Advanced - under the advanced panel of the file arrival trigger, you can select how often the trigger checks for new files. It can also be used to set a delay once a new file has been detected

Task Parameters

- Paramemters Tab
  - Key: Value
  - Job parameter; set at job level, visible to all tasks. A job parameters value will always override a task parameter
  - Task parameter; set at task level, visible to that task only
  - Task Parameters can be used to support logic like looping or conditional executon. a job parameter would be too broad
